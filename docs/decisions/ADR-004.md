# ADR-004: 运营后台前端技术栈（React + TypeScript + Vite + Ant Design + Phosphor）

## Status: Accepted (2026-10-02)

## Background

Spec v0.2 新增「内容维护与运营后台」（§7.2），为独立 Web App（项目总监裁决：不混入儿童 App 包体，分域部署）。后台是表格/表单密集型内部工具（内容编辑器、媒体库、审计日志、用户管理），非面向公众，无 SEO/SSR 需求。同时必须遵守 P0 规则：

- 图标库全产品唯一 = **Phosphor Icons**（项目总监裁决，覆盖原 Lucide 方案），禁 emoji、禁混用
- 禁紫色→粉色渐变方案
- 禁硬编码色值（#fff/#000 除外），颜色一律走设计 Token（Spec §8 后台主题映射）

## Decision

| 层 | 选型 | 版本锚定 | 理由 |
|----|------|----------|------|
| 框架 | React + TypeScript + Vite | React 18.x / TS 5.x / Vite 5.x | Spec §4 已锁定；纯静态产物可直接部署 CloudBase 静态托管；无 SSR 需求不引入 Next.js 复杂度 |
| 路由 | React Router v6（数据路由 createBrowserRouter） | 6.x | 表格式多页面（10 页），loader/action 与 TanStack Query 配合清晰；生态默认选项 |
| 服务端状态/请求 | TanStack Query | 5.x | 与儿童 App 同栈（zustand + react-query ^5），团队/代码经验复用；缓存失效天然契合「审核通过→列表刷新」流 |
| 客户端状态 | Zustand（仅 UI 态：筛选栏、抽屉开关） | 5.x | 同上，最小引入 |
| 表格 | Ant Design 5 Table | 5.x | 筛选/分页/排序开箱即用，不再叠加独立表格库 |
| 表单/校验 | React Hook Form + Zod | RHF 7.x / Zod 3.x | 内容编辑器字段多、条件校验复杂；Zod schema 与 openapi.yaml 生成的 TS 类型对齐（单源） |
| 组件库 | Ant Design 5 | 5.x | B 端效率优先；Layout/Form/Upload/Modal/Message 全覆盖 |
| 图标 | @phosphor-icons/react | 最新稳定 | P0 一致性硬约束；**禁用 @ant-design/icons**，AntD 组件的 icon 插槽一律传 Phosphor 组件 |
| 样式 | AntD ConfigProvider token + `design-tokens.css`（CSS variables） | — | 后台主题由设计师 Token 映射（Spec §8）；业务代码零硬编码色值 |
| 部署 | CloudBase 静态托管，独立域名/子路径 | — | 分域（Spec §14.5） |

**媒体上传方案**（对齐 `POST /api/v1/admin/media`，Spec §14.5）：

1. 前端提交元数据 `{folder, fileName, mime, size, width?, height?, durationMs?, itemId?}` → 后端校验 mime/size 上限（来自 `GET /admin/settings`）→ 生成确定性对象键 `admin-media/{folder}/{yyyymm}/{uuid}-{fileName}` → 落 `media_assets` 记录 → 返回 `{mediaId, cdnKey, cdnUrl, upload: {tmpSecretId, tmpSecretKey, sessionToken, storagePath, expiresInSec=1800, maxFileSize}}`（COS 临时密钥，路径白名单仅限该 cdnKey）。
2. 前端用临时凭证**直传**云存储（cos-js-sdk-v5 或 @cloudbase/js-sdk），不经过后端。
3. 直传成功后前端以返回的 `cdnKey` 填充内容表单的 `cover` / `mediaRef` 字段。
4. 直传放弃/失败 → `DELETE /admin/media/{id}` 清理孤儿记录（admin 权限；editor 场景由 `AdminSettings` 决定是否允许，默认 editor 仅可清理自己未引用的记录——见未决项）。
5. 审计：`admin.media.upload` 在 POST 落库时写入。

## Consequences

正面：
- 全静态部署、零服务端运维；与儿童 App 技术栈（React/TS/TanStack Query/Zustand）最大复用。
- AntD 5 把 10 个后台页面的表格/表单成本压到最低，符合「列表页 <1.5s」性能约束（按需引入 + 路由级 code-splitting）。
- Zod + openapi.yaml 单源：前端类型由 `openapi.yaml` 生成（openapi-typescript），杜绝前后端形状漂移。

负面 / 风险：
- AntD 默认图标包（@ant-design/icons）与 Phosphor 混用是最大风险 → 以 ESLint 规则禁用 `@ant-design/icons` import 作为门禁。
- AntD 5 默认主题偏蓝，必须通过 ConfigProvider token 映射到薄荷青 `#12B5A6` 品牌色，禁止紫粉系。
- 临时凭证直传依赖前端时钟/网络，凭证过期需提示重新发起 POST。
